方案 B3

端侧模型翻译：把算力交给用户设备

底层逻辑：不经过任何服务器。Chrome 138+ 内置 Gemini Nano，提供 Translator API（translation.createTranslator({sourceLanguage:'en', targetLanguage:'zh'})）。reader 页在浏览器本地下载模型后逐段翻译——离线、免费、隐私、无跨境网络问题。

工作方式

reader 页检测 'translation' in window && 可用语言对 → 首次使用触发模型下载（GB 级，浏览器管） → 逐段 translate()，中文插入英文段下方 → 无网络请求、无 key、无服务器成本

成本

免费
  • 零后端、零 API 费用；管线与契约零改动。
  • 代价转移到用户侧：Chrome 138+、能跑得动端侧模型的设备、首次模型下载（大且耗时）。

优点

  • 对大陆用户天然免疫——不依赖任何境外端点；
  • 隐私好（内容不出设备），无速率限制；
  • 段落级翻译速度不错（本地推理），滚动翻译体验接近即时。

局限与风险

  • 可用性门槛：需要较新 Chrome + 足够内存/存储；覆盖面无法保证（需要特性检测 + 优雅降级）；
  • 首次使用要下载模型（可能数百 MB 到数 GB），首次体验差；
  • 小模型质量低于云端 LLM，长难句/术语一般；
  • API 形态较新，可能有变更风险（需要封装隔离）。

适合谁

  • 作为「无译文条目的本地兜底」非常合适：有 Nano 就一键本地翻，没有就隐藏按钮。不建议作为唯一翻译源——用户设备参差不齐，无法承诺一致性体验。
