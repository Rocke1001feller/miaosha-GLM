脑暴 · 双语阅读体验的「锚定粒度」

从「段对段」到「句对句」

现状：双语已实现块级上下对照（英文段落下接中文段落）。反馈：块一长，读完英文长段再读中文长段， 句与句的关联彻底丢失。目标：找到最好的双语对照体验，同时保持项目的简洁优雅。

一、问题的本质：不是翻译问题，是「锚定」问题

本质 1：双语的可用性 = 锚定成本

读者读双语时，大脑一直在做一件事：把这句中文和它的英文原句对上号。对上的成本越低，体验越好。 锚定成本由对照粒度决定：篇对篇 ≫ 段对段 ≫ 句对句 ≫ 行内同句。 当前实现停在「段」，而新闻段落动辄 5–8 行，段内多句，关联就在段内丢了——这就是你体验的断点。

本质 2：粒度是一条光谱，不是一个点

粒度越细，锚定越强，但排版噪声越大、阅读越被打断。而且不同的人要的不一样： 学英文的人要句级对照；只想获取信息的人要中文流畅、英文只作"锚点备用"。 所以最优雅的答案不是替用户选一个粒度，而是把粒度做成可切换的视图——句/段/单语，一键切换。

本质 3：对齐正确性必须在数据源头保证

句级对照的难点不在渲染，在对齐：英文 3 句翻成中文可能是 2 句，靠前端切句再配对，错位是常态。 唯一可靠的做法是让「句」成为管线的翻译与存储单位——按句翻译、按句存对， 渲染层不做任何对齐猜测。这恰好也符合我们一贯的原则：把运行时问题变成构建时问题。

最终实施建议

  1. 主线：方案一（句级翻译契约）。管线把翻译单位从段降为句（英文分句用正则即可），快照存 blocks: [{html_en, sentences: [{en, zh}]}]；reader 句级交替渲染（英文原句→灰色中文句），对齐在源头保证，渲染零猜测。缓存键改为句级，新增请求约 ×3，但缓存永续复用，且已有段级缓存命中的内容可整段跳过。
  2. 交互：顺手落实方案五的粒度开关。顶栏从「双语/中文/EN」扩为「双语·句 / 双语·段 / 中文 / EN」——句级数据同时能组装出段级视图，零额外成本。
  3. 方案二作过渡验证（可选）。若你想今天就看到句级效果而暂不动管线，可用前端切句快速验证交互；但不要长期依赖——启发式对齐的错误会悄悄累积。
  4. 方案三/四不入主线。左右双栏对窄屏和打印不友好；点按揭示与"打开即双语"的预期相悖。两者都可作为日后阅读页的实验性视图，但不值得现在付复杂度。

简洁优雅如何保持：新概念全部落在已有层——句级翻译仍在 snapshot 步骤内（替换的是 fulltext 的遍历单位）；快照契约从"HTML 镜像"演进为"句对数组"；reader 从"对齐渲染"简化为"按契约渲染"。管线缓存、预算、降级策略全部原样复用。
