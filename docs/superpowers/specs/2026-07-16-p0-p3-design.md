# P0 开火策略重写 + P3 支付链直连设计文档

## 1. 目标与边界

### 1.1 目标
- **P0**：将现有基于并发齐射的自动/手动开火策略，替换为「低预算、低频率、时钟校准、翻转触发」的精准策略，以提升在 UTC+8 10:00:00 创建订单的成功率。
- **P3**：对 `payType=ALI` 的订单，在 preview 成功后跳过 PayComponent 弹窗，直接从 MAIN world 调用 `/api/biz/pay/create-sign` 拿到收银台 URL 并新标签打开；失败时回退到原生弹窗二维码。`WE_CHAT` 保持原生弹窗二维码链路不变。

### 1.2 不做的事
- 不改动验证码录入、票仓 sessionStorage 结构、background 的 badge/alarm、popup/options 页面、火山引擎侧代码。
- 不新增第三方依赖（crypto-js 等）；WE_CHAT 仍走官方桌面二维码链路。
- 不改动 `lib/platform` 的抽象接口，只扩展现有字段的使用。

## 2. 实测事实（设计约束）

- preview 端点：累计约 15 发即触发 WAF 405 封锁 30–60 分钟；单账号维度计数，与请求来源（extension/页面）无关。单发间隔 <2s 会返回 555，并发第二发必 555。
- batch-preview 端点：与 preview 分桶；约 1 次接受/4s，2.2s 间隔呈 200/555 棋盘格，10 次内不触发 405。
- 票：腾讯验证码 ticket TTL 300s；soldOut/555 响应不核销 ticket；核销只发生在库存门放行时。
- 时钟：本地时间比服务器快约 343ms，需从 batch-preview 响应 `Date` 头估算 `serverOffsetMs`。
- 订单创建：唯一稀缺资源是库存；支付有 30 分钟以上窗口，不必急着支付。
- create-sign 桌面分支：官方桌面端 `media.isPhone=false` 时只渲染 AES 二维码，不调用 create-sign；手机端及 H5 链直接调用 create-sign，API 本身无客户端门禁。
- create-sign 响应：200 + `data.sign` 为收银台 URL，`data.orderId` 为订单号。
- 客户号来源：`GET /api/biz/customer/getCustomerInfo` 返回用户 profile，含 `customerNumber`。

## 3. P0 开火策略设计

### 3.1 新增 `lib/api/smart-fire-plan.ts`
纯函数状态机，核心接口：

```ts
export interface SmartFireState {
  tickets: Ticket[];           // 按 createdAt 升序， freshest 在后
  selectedIds: string[];       // 优先级顺序
  budgetLeft: number;          // 默认 8
  shotsFired: number;
  lastShotAt: number;          // ms
  stockOpen: boolean;
  serverOffsetMs: number;      // 本地减 server
  nextSaleTime: number;        // 本地配置的 sale epoch
  mode: 'auto' | 'manual';
}

export type FireEvent =
  | { kind: 'TICK'; now: number }
  | { kind: 'STOCK_FLIP'; now: number }
  | { kind: 'RESULT'; outcome: 'success' | 'soldout' | 'busy' | 'waf405' | 'captchaInvalid' | 'error'; now: number };

export interface FireDecision {
  action: 'fire' | 'wait' | 'stop';
  shot?: {
    productId: string;
    ticket: Ticket;
    scheduledAt: number;
  };
  nextState: SmartFireState;
  reason: string;
}

export function nextDecision(state: SmartFireState, event: FireEvent): FireDecision;
```

#### 决策规则
1. **停止条件**：`budgetLeft <= 0`、收到 `waf405`、`captchaInvalid`（ticket 真死）、所有 ticket TTL 耗尽，或 `RESULT=success`。
2. **首发时机**：
   - 自动模式：`saleTime - serverOffsetMs - 10ms`（本地时间）。
   - 若在此之前收到 `STOCK_FLIP`，立即发射。
   - 手动模式：点击 Fire 时立即发射。
3. **补发时机**：上一发结束后等待 `MAX(2200, lastShotAt + 2200 - now)`，使用同一张 ticket（若上发为 555/soldOut 不消耗 ticket）或下一张 freshest ticket。
4. **目标选择**：每次取 `selectedIds[0]` 作为主攻；若 `selectedIds` 有多个且主目标持续 soldOut，可在第 3 发后轮换到下一个（实现时保留扩展点，默认不轮换）。
5. **不消耗 ticket 的失败**：`555` / `soldOut` 不把 ticket 从池子里移除，状态机记录同一张 ticket 可继续用。

### 3.2 新增 `src/bm-main/06-stock-watch.js`（MAIN world）
职责单一：在页面上下文里以官方指纹持续观察库存与身份。

#### 3.2.1 客户号预取
页面加载后 500ms：
```js
fetch('https://bigmodel.cn/api/biz/customer/getCustomerInfo', {
  method: 'GET',
  credentials: 'include',
  headers: getLocalAuthHeaders(),
})
.then(r => r.json())
.then(d => {
  if (d.code === 200 && d.data) {
    window.__bm_customerInfo = d.data;
  }
});
```
`getLocalAuthHeaders()` 复用 `05-product.js` 的同源实现：从 `document.cookie` 取 `bigmodel_token_production`，从 `localStorage` 取 `Bigmodel-Organization` 和 `Bigmodel-Project`。

#### 3.2.2 库存轮询
- 从 `nextSaleTime - 90000` 开始轮询 `POST /api/biz/pay/batch-preview`。
- 周期：**4300ms**（经验值，低于 WAF 阈值，又能较快捕捉翻转）。
- 使用 `window.fetch`（带页面 Sentry 插桩），认证头与页面一致。
- 每次成功响应：
  - 用 `Date` 头 + RTT/2 更新 `window.__bm_serverOffset`（取运行最小值）。
  - 更新 `window.__bm_stockState`（每个 selected product 的 soldOut）。
  - 若检测到任意 selected product 从 `soldOut=true` 变为 `soldOut=false`，向 ISOLATED world 发送 `STOCK_FLIP` 事件：
    ```js
    window.postMessage({ __miaosha: true, type: 'STOCK_FLIP', payload: { serverNowMs: Date.now() - window.__bm_serverOffset, productIds } }, '*');
    ```

#### 3.2.3 与现有 05-product.js 的关系
- `05-product.js` 负责初始产品矩阵加载，调用一次 batch-preview。
- `06-stock-watch.js` 负责战前持续轮询，不重复 `05-product.js` 的加载逻辑，只消费 soldOut 状态变化。

### 3.3 `entrypoints/bm-capture.content.ts` 改造

#### 3.3.1 删除旧策略
- 删除 `runAutoFirePlan`。
- 删除 `burstStrike` 及其 `200ms` 自杀模式。
- 删除对 `lib/api/fire-plan.ts` 的导入与使用。
- 保留 `lib/api/strike-plan.ts` 用于构造手动射击队列（仍需优先级/轮询）。

#### 3.3.2 新增 MAIN-world fetch 中继
在 `02-state.js` 或本文件中新增请求/响应中继：
- ISOLATED world 发送 `PAGE_FETCH_REQUEST`：{reqId, url, method, headers, body}。
- MAIN world 用 `window.fetch` 执行，返回 `PAGE_FETCH_RESPONSE`：{reqId, status, headers, bodyText}。
- 该中继用于 preview（以及可选的 create-sign，但 create-sign 放在 `10-native-pay-trigger.js` 更直接）。

#### 3.3.3 接入 `smart-fire-plan`
- 维护一个 `SmartFireState` 实例。
- 监听 `STOCK_FLIP` 事件 → 调用 `nextDecision(state, {kind:'STOCK_FLIP', now})`。
- `07-auto-fire.js` 在 `T-10ms` 触发 `PREFIRE_FIRE reason:'auto'` → 进入新自动策略。
- 手动 Fire → `PREFIRE_FIRE reason:'manual'` → 进入手动策略。
- 每发 preview 走 MAIN-world fetch 中继，计数预算；收到响应后根据分类更新状态机，决定下一发或停止。

#### 3.3.4 手动模式约束
- `fireConfig.burstIntervalMs` 下限强制改为 **2100ms**（无论存储值多小）。
- 手动模式同样走 `smart-fire-plan`，初始 budget 也为 8。

### 3.4 UI 去留
- `08-overlay.js`：删除 `_fbb`（BURST 按钮）及其事件监听。
- `09-fire-viz.js`：清理 `BURST_FIRE_SUCCESS`/`BURST_FIRE_DEPLETED` 中仅用于 BURST 的特殊渲染（保留事件订阅，只是不显示 BURST 专用控件）。
- force-stop banner：移除 `BURST` 按钮，只保留 `Fire 串行` 和 `Esc 停止`。

## 4. P3 支付链直连设计

### 4.1 `10-native-pay-trigger.js` 改为支付分发器
当前逻辑：收到 `BURST_FIRE_SUCCESS` 即打开 PayComponent 弹窗。
新逻辑：

```js
window.addEventListener('message', function(e) {
  if (!e.data || e.data.__miaosha_overlay !== true) return;
  if (e.data.type !== 'BURST_FIRE_SUCCESS') return;
  var ps = e.data.data;
  if (!ps || !ps.bizId) return;

  if (ps.payType === 'ALI' && window.__bm_customerInfo && window.__bm_customerInfo.customerNumber) {
    directCreateSign(ps);
  } else {
    openNativePaymentDialog(ps);
  }
});

function directCreateSign(ps) {
  var auth = getLocalAuthHeaders();
  var ic = new URLSearchParams(window.location.search).get('ic');
  var body = {
    payType: 'ALI',
    productId: ps.productId,
    customerId: window.__bm_customerInfo.customerNumber,
    bizId: ps.bizId,
  };
  if (ic) body.invitationCode = ic;

  fetch('https://bigmodel.cn/api/biz/pay/create-sign', {
    method: 'POST',
    credentials: 'include',
    headers: Object.assign(auth, {
      'Content-Type': 'application/json;charset=utf-8',
      'accept': 'application/json, text/plain, */*',
    }),
    body: JSON.stringify(body),
  })
  .then(r => r.json())
  .then(d => {
    if (d.code === 200 && d.data && d.data.sign) {
      postToOverlay({ type: 'PAYMENT_CREATED', data: { bizId: ps.bizId, orderId: d.data.orderId, payType: 'ALI' } });
      chrome.runtime.sendMessage({ type: 'OPEN_PAY_TAB', url: d.data.sign });
    } else {
      openNativePaymentDialog(ps);
    }
  })
  .catch(() => openNativePaymentDialog(ps));
}
```

### 4.2 `entrypoints/background.ts` 新增 `OPEN_PAY_TAB`
```ts
if (msg.type === 'OPEN_PAY_TAB') {
  chrome.tabs.create({ url: msg.url })
    .then(() => sendResponse({ ok: true }))
    .catch((err) => sendResponse({ ok: false, error: err?.message || String(err) }));
  return true;
}
```

### 4.3 fallback 路径
- `create-sign` 非 200、无 `data.sign`、网络异常、`customerNumber` 缺失、或 `payType !== 'ALI'` 时，全部回退到现有 `openNativePaymentDialog`。
- 该弹窗会渲染 AES 二维码，与官方桌面链路一致，用户可扫码继续支付。

### 4.4 `order-pipeline.ts` 字段对齐
当前 preview body 只发 3 个字段，补上 `invitationCode: ''`：
```ts
body: JSON.stringify({
  productId: ctx.productId,
  invitationCode: '',
  ticket: ctx.ticket.ticket,
  randstr: ctx.ticket.randstr || '',
}),
```

## 5. 数据流图

```
[06-stock-watch.js] MAIN world
    │
    ├── fetch getCustomerInfo ──> window.__bm_customerInfo
    │
    ├── poll batch-preview ─────> window.__bm_serverOffset
    │                              window.__bm_stockState
    │                              postMessage STOCK_FLIP
    │
[bm-capture.content.ts] ISOLATED world
    │
    ├── receive STOCK_FLIP ─────> SmartFireState
    │
    ├── auto/manual trigger ─---> nextDecision() ──> PAGE_FETCH_REQUEST
    │
[MAIN world fetch relay] <────── PAGE_FETCH_REQUEST
    │
    └── window.fetch preview ─--> PAGE_FETCH_RESPONSE
    │
[bm-capture.content.ts] on success
    │
    └── postMessage BURST_FIRE_SUCCESS

[10-native-pay-trigger.js] MAIN world
    │
    ├── if ALI + customerId ────> fetch create-sign ──> OPEN_PAY_TAB
    │
    └── else ───────────────────> openNativePaymentDialog (WE_CHAT / fallback)
```

## 6. 安全与风控硬线

| 风险 | 措施 |
|---|---|
| preview WAF 405 | 默认预算 8，遇到 405 立即停止并 UI 告警；手动模式也计预算。 |
| 并发 555 | 单线程串行，最小间隔 2100ms；`fireStore.burstIntervalMs` 下限强制 2100ms。 |
| 盲目齐射 | 删除 BURST 200ms 模式；auto-fire 用 `serverOffsetMs` 校准而非本地 T-10ms。 |
| 票被误烧 | 555/soldOut 不把 ticket 从池子移除；状态机可复用同一张票。 |
| create-sign 失败 | 所有失败路径回退原生弹窗，不中断支付。 |
| 请求指纹 | preview 与 create-sign 均走 MAIN world `window.fetch`，与页面自身请求一致。 |

## 9. 决策记录

- **不等待用户 review 书面 spec**：用户在口头设计阶段已明确「请立即开始执行直到任务全部完成」，因此直接进入 writing-plans 与实施。
- **WE_CHAT 不走 create-sign 直连**：桌面浏览器打开微信收银台 URL 的可用性未验证，官方桌面链路就是扫码，保持最稳妥路径。
- **preview 请求走 MAIN world**：虽然 background proxy 在和平期可用，但 war-time WAF 可能对 extension-origin 更敏感；MAIN-world fetch 使指纹与官方页面完全一致。
