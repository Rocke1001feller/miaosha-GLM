Coding Plan 横评系统 — 5 种底层逻辑方案预览

目标：把市面上 coding / agent / token plan 拉到同一基准，剥掉营销外衣，让用户一站式看清 「谁质优量大、谁在玩文字游戏」。本页汇总 5 个可打开的设计原型，全部填入 2026-07-17 调研快照的真实数据（小米 MiMo / MiniMax / 智谱 GLM / Kimi）， 共享同一份统一事实模型 shared/data.js。

方案 01

统一度量衡仪表盘

底层逻辑：万物归一——先把 Credits / prompts / 百分比池全部折算成同一基准（标准任务轮、轮/元），数字才有资格并排。
擅长回答
「同样 100 块，谁给的真量多？」「营销面值注了多少水？」
局限
依赖折算假设，任务形态不同会有数倍偏差；不擅长呈现条款细节。

方案 02

营销-文档对撞台

底层逻辑：文本并置证伪——左边放营销页原话，右边放文档页条款，让两组原文自己对撞出水分。
擅长回答
「这家的话术和合同差多远？」（小米 1320亿 vs 600 Credits/token 的对撞现场）
局限
跨厂商横向排序能力弱；阅读量大，适合详情页不适合首页。

方案 03

用量模拟计算器

底层逻辑：以用户用量模型为中心——数据变参数化规则，答案算出来而不是查出来（高峰 3x、夜间 0.8x、周窗口全部建进公式）。
擅长回答
「按我的用法，额度几号耗尽？」「我该买哪一档？」
局限
交互成本最高；规则需随各厂条款变化持续维护。
打开原型 →
方案 04

消费报告评级卡

底层逻辑：专家规则引擎——5 个固定维度 A/B/C 评级，像消协报告一样先公开判定标准再给红绿灯。
擅长回答
「给我 30 秒，告诉我谁家不能碰、谁家可以闭眼买。」
局限
评级含主观权重；需要明确的 rubric 与定期复评机制背书。
打开原型 →
方案 05

陷阱模式图鉴

底层逻辑：按套路而非按公司组织——7 种营销反模式（单位混淆/高峰惩罚/共享池连坐/速度税…），授人以渔。
擅长回答
「下次再遇到新厂商，我自己怎么识破套路？」
局限
教育导向强、决策导向弱；需要持续收录新套路保持时效。

横向对比

方案组织主线信息处理交互性最适合场景二期 UGC 亲和度
01 度量衡仪表盘统一指标数值归一低（静态图表）首页横评总览中（数值区可叠加用户实测）
02 对撞台信息源双轨原文并置低单厂商详情页高（用户可补充"我的遭遇"对照）
03 模拟器用户用量规则引擎高（实时计算）选购前决策工具低
04 评级卡评判规则专家打分低速览/传播高（官方评级 + 用户评分双轨）
05 图鉴反模式分类归纳教育中（自查清单）方法论栏目高（用户投稿新套路）

我的判断：不是五选一，而是分层组合

五个方案回答的是决策链上不同环节的问题，真正的一期产品应该是一个数据层 + 五个视图： 共享的统一事实模型（现在的 shared/data.js，未来演进为 JSON API + 定期抓取的清洗管道）之上——

  1. 01 度量衡仪表盘做首页骨架：统一基准是系统存在的意义，先让用户看到"谁在注水"。
  2. 04 评级卡做速览层与传播层：30 秒决策入口，也是二期用户评分的天然落点。
  3. 02 对撞台做厂商详情页：点进每家看营销与条款的原文对撞。
  4. 05 图鉴做方法论栏目：沉淀反模式库，二期开放用户投稿新套路。
  5. 03 模拟器做工具页：选购前的"按我的用法算一卦"，条款变化时只需更新规则参数。

若必须先做最小验证，建议从 01 + 04 起步（覆盖"横评总览 + 速览决策"两个最高频场景）。
